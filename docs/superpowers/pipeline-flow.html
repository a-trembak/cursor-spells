6. review-gate

HITL після коду, перед engineer-review. Шар плану вже закритий. Пайплайн не закінчується тут. Команда /csp-finish-plan пише .cursor/gates/review-gate/<slug>, потім review-surface.

1

review-surface (зручність, не фінал)

Checkout feature branch у кожній відкритій папці. SetActiveBranch — вкладка diff / pull request у клієнті. Не create-pr, не GitHub pull request. Коли гілка має 0 commits ahead of base, вкладка може бути порожньою — спочатку Local Diff Review canvas (плагін local-diff-review / skill review-local-diff; Send на Current thread пише outbound local-diff-review/comments). Якщо плагіна немає — покажи uncommitted робоче дерево в чаті (git status / git diff). Після відповіді людини стартує engineer-review, далі propose-commit, docs, далі create-pr.

7b. propose-commit

HITL після settled engineer-review і Teach-review miss. Спочатку skill local-diff-review-gate (approve-diff / comment), потім пропонує commit message + file list; людина відповідає approve-commit або revise. Лише git commit — ніколи push чи GitHub pull request. Пише .cursor/gates/commit-approved/<slug>. На full path далі update-docs; якщо після docs лишились uncommitted файли — ще раз local-diff-review-gate, потім другий propose-commit, потім create-pr.

1

2

Завжди draft спочатку. Потім один HITL. Ніколи merge. ready / ready_jira з ключем → Jira review лише після merge всіх PR і успішного CI.

Markers · state

Усі маркери в consumer project .cursor/gates/<kind>/<slug>, не в kit. Паралельні тікети — різні slug; чужий slug не блокує цей план. Stop-хуки нагадують лише коли відомий шлях поточного плану. Якщо шлях невідомий — мовчать, щоб не зациклити чужий чат. Legacy flat-файли мігрують при читанні.

Standalone entry points

Lean paths, bug-fix pipeline, create-pr finale, та команди поза повним оркестратором.

·

create-pr (фінал кожного пайплайна)

Skill create-pr: push + завжди draft, потім HITL Pipeline finale (keep_draft / ready / keep_draft_jira / ready_jira). Не merge. Потребує commit-approved marker від propose-commit. Викликається після update-docs (+ residual propose-commit) у full /csp-start-task, після propose-commit у --fast та /csp-start-issue-task.

·

/csp-start-task --fast

Без tech-spec / plan / critic / review-gate / docs: fetch (якщо ticket) → jira-transition in_progress → brief → csp-software-developer mode:fast → csp-engineer-reviewer → local-diff-review-gate → propose-commit → create-pr finale. Якщо class=bug — HITL Fast vs issue. Агент ніколи не обирає --fast.

·

/csp-start-issue-task

jira-fetch → jira-transition in_progress → fix plan → critic Pass A/B/C → HITL лише якщо blocked → csp-bug-fixer → csp-engineer-reviewer → local-diff-review-gate → propose-commit → create-pr finale. Explicit command завжди лишається на issue path, навіть якщо type=Story.

·

/csp-write-tech-spec

Лише tech-spec, без решти пайплайна. Якщо AC source схожий на Jira — той самий jira-fetch.

·

/csp-critique-plan

Ad-hoc critic. Не замінює approve-plan gate і сам не готує build clear-marker як pipeline path.

·

/csp-approve-plan → /csp-start-build

Повний pre-build gate вручну: HITL approve, auto critic, clear → build.

·

/csp-finish-plan · /csp-engineer-review · /csp-update-docs · /csp-pr-review · /csp-multi-review · /csp-capture-escape

/csp-finish-plan входить у review-gate HITL (код уже написаний). Manual /csp-engineer-review пропускає цей HITL; /csp-update-docs лишається окремим HITL destination gate. /csp-pr-review за замовчуванням будує PR Review Canvas (орієнтація по diff), потім validated Findings; no-canvas пропускає canvas. /csp-capture-escape питає miss (kit через teach-review) або project_secret (локальний ledger). /csp-teach-review після validated miss пише generalized kit instructions на remote learn/… і відкриває ready-for-review pull request (не consumer ledger, окрім коли обрано project_secret).
