Standalone entry points

Lean paths, bug-fix pipeline, create-pr finale, та команди поза повним оркестратором.

·

create-pr (фінал кожного пайплайна)

Skill create-pr: commit/push + завжди draft, потім HITL Pipeline finale (keep_draft / ready / keep_draft_jira / ready_jira). Не merge. ready / ready_jira з Jira-ключем → jira-transition target review. Викликається після update-docs у full /start-task, після engineer-review у --fast та /start-issue-task.

·

/start-task --fast

Без tech-spec / plan / critic / review-gate / docs: fetch (якщо ticket) → jira-transition in_progress → brief → software-developer mode:fast → engineer-reviewer → create-pr finale. Якщо class=bug — HITL Fast vs issue. Агент ніколи не обирає --fast.

·

/start-issue-task

jira-fetch → jira-transition in_progress → fix plan → critic Pass A/B/C → HITL лише якщо blocked → bug-fixer → engineer-reviewer → create-pr finale. Explicit command завжди лишається на issue path, навіть якщо type=Story.

·

/write-tech-spec

Лише tech-spec, без решти пайплайна. Якщо AC source схожий на Jira — той самий jira-fetch.

·

/critique-plan

Ad-hoc critic. Не замінює approve-plan gate і сам не готує build clear-marker як pipeline path.

·

/approve-plan → /start-build

Повний pre-build gate вручну: HITL approve, auto critic, clear → build.

·

/finish-plan · /engineer-review · /update-docs · /pr-review · /multi-review · /capture-escape

/finish-plan входить у review-gate HITL (код уже написаний). Manual /engineer-review пропускає цей HITL; /update-docs лишається окремим HITL destination gate. /pr-review за замовчуванням будує PR Review Canvas (орієнтація по diff), потім validated Findings; no-canvas пропускає canvas. /capture-escape пише production miss у review-learn без повного review.
